# MY OSM

*Français : [README.fr.md](README.fr.md)*

A local mapping app built on OpenStreetMap: vector map, shops and opening hours,
routes and step-by-step guidance, public transport departures and journeys. One
codebase, shipped in two forms: an **installable website** and an **Android app
(APK)**.

Downloads: see [Releases](https://github.com/Gris-S/my-osm/releases).

## Project layout

```
MY OSM/

├── README.fr.md     ← the same, in French
├── CLAUDE.md        ← instructions for Claude (points to app/CLAUDE.md)

│   ├── src/             all the application code
│   ├── public/          icons, favicon
│   ├── scripts/         generation tools (icons, dark style…)

│   └── CLAUDE.md        technical rules and architecture decisions (French)
│
├── apk/             ← THE ANDROID WRAPPER (Capacitor) — no app logic
│   ├── capacitor.config.ts   name, identifier, points to app/dist
│   ├── android/              Android project generated by Capacitor
│   └── README.md             build, toolchain, known limits (French)
│
├── docs/            ← architecture of the transport layer, audit (French)
│
├── livrables/       ← WHAT GETS INSTALLED (not in the repository)
│   ├── MY-OSM-debug.apk      latest working APK (debuggable)
│   ├── MY-OSM.apk            latest APK to share (release)
│   └── anciens/              previous APKs, dated
│
├── saves/           ← DATED BACKUPS, one per major change (not in the repository)
│   └── YYYY-MM-DD_NN_description/
│
└── outils/
    └── save.sh      ← creates a backup in saves/
```

**Golden rule:** code is only changed in `app/`. `apk/` just packages what
`app/` produces.

## Common commands

```bash
# Web version, in development
cd app && npm run dev

# Build the APK (rebuilds the web app, then Android, then copies it to livrables/)
source ~/.local/share/android-env.sh
cd apk && npm run apk

# APK to share: not debuggable, no diagnostic tools (livrables/MY-OSM.apk)
cd apk && npm run apk:release

# Install the APK on a phone connected over USB
cd apk && npm run install

# Read the navigation log of the connected phone (app open)
outils/journal.sh

# Make a backup
outils/save.sh "short-description"
```

## API keys

No key is required: the app works without them, and public transport then runs
on Transitous everywhere. Optional free keys (Île-de-France Mobilités PRIM,
TomTom, Mapillary, Météo-France) can be entered in the app (Menu › API), or put in
`app/.env.local` for a local build (see `app/.env.example`). They are never
committed.

## Backups

After each major change, a copy of the project is made in `saves/`, named
`YYYY-MM-DD_NN_description`: the date, a sequence number, and what had just been
done. They therefore sort chronologically on their own.

To stay light, they **do not include** what can be regenerated: `node_modules/`,
`app/dist/`, Android `build/` folders, or `livrables/`.

**Restoring a backup:** copy its contents to the root of `MY OSM/`, then run
`npm install` in `app/` and in `apk/`.

The first three (`01` to `03`) are copies made by hand before this organisation;
they still contain their `node_modules`. `00` is the archive of the very first
version.
